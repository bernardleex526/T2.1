# 测试场景与统计口径（T2.1）

> 本文档补齐评审报告指出的缺口 3：需求要求"可复现的验证方法（**含回环路线**、测量工具、统计口径）"，
> 而仓库此前只有合成矩形轨迹。本文给出**真实场景回环测试方案**与**统一的统计量定义**。
>
> **本文档中的场景参数（路线长度、圈数、控制点数量）是方案建议，不是已执行的记录。**
> 执行结果必须单独归档，不要写回本文档充当"已验证"。

---

## 1. 统计口径统一（先定义，再测量）

评审指出仓库文档混用多种统计量。以下为**唯一口径**，任何报告中的数字都必须注明所用口径。

### 1.1 建图精度

| 项 | 定义 |
|:---|:---|
| 指标 | `point-to-plane RMSE`（点到参考平面距离的均方根） |
| 聚合 | **全图所有点**的 RMSE，不做下采样后再算 |
| 参考 | 合成场景用解析几何面；真实场景用全站仪/RTK 控制点拟合的平面 |
| 验收 | ≤ 0.05 m |
| 已知量化下限 | `scan_resolution` 决定体素尺寸。**`scan_resolution: 0.3` 时，地图点被量化到 0.3 m 网格，单此一项就已排除任何"亚分米级精度"的声明**（见 `lio_highres.yaml` 头部注释）。要声明 5 cm 级精度，`scan_resolution` 必须显著小于 5 cm。 |

> ⚠️ 合成环境的 2.77 cm RMSE 是在**解析平面**上测得的；真实场景的参考面本身有不确定度，两者不可直接比较。

### 1.2 定位精度

| 项 | 定义 |
|:---|:---|
| 指标 | `ATE`（Absolute Trajectory Error），位置部分 |
| 聚合 | 所有时间戳上的 RMSE |
| 时钟口径 | **必须注明**：`当前查询时钟`（current）或`发布时间戳`（stamp）。二者差异极大——仓库实测中发布戳 ATE 为 1.81–2.23 cm，而当前时钟口径可达 5.91–18.78 cm。 |
| 验收 | ≤ 0.05 m |

**两种口径都要报**，并明确标注。只报发布戳会掩盖真实使用场景下的误差。

### 1.3 定位可用率

| 项 | 定义 |
|:---|:---|
| 指标 | 输出有效位姿的时间戳比例 |
| 分段 | **全段可用率**与**后锁可用率**必须分开报 |
| 验收 | 全段 ≥ 95%（需求）；后锁 ≥ 95% |
| 已知问题 | 仓库实测全段 88.58%、后锁 99.53%。**全段不达标的主因是启动时间 6.62 s**（占总损失 96.35%），即"启动慢"而非"运行中丢失"。因此优化方向是启动时间，不是门控阈值。 |

### 1.4 建图速度

| 项 | 定义 |
|:---|:---|
| 指标 | 每帧处理延迟的 p50 / p95 / p99 |
| 预算 | 10 Hz 输入 → 单帧 ≤ 100 ms |
| 验收 | p95 ≤ 100 ms；丢帧率 0% |
| 等效速度 | `实时因子 × 运动速度`。仓库实测实时因子 1.02 → 0.5 m/s × 1.02 = 0.51 m/s。**这是"能跟上"的证明，不是"跑得快"的证明**，不要外推。 |

### 1.5 回环检测

| 项 | 定义 |
|:---|:---|
| 指标 | 每圈闭合误差（欧氏距离）、回环检测成功率 |
| 聚合 | 每圈单独报，不要只报均值 |
| 验收 | 每圈闭合误差 ≤ 5 cm；回环成功率 ≥ 90% |

## 2. 合成环境（已有，可复现）

### 2.1 场景与命令

```bash
# 场景：10×10 m 室内房间 + 4 根立柱；闭合矩形轨迹，总长 40 m；0.5 m/s 恒速
# LiDAR：合成点云 10 Hz，约 24k 点/帧；IMU：合成 200 Hz（含 20 Hz、±5° 步态振荡）

# T1 建图精度
python3 simulation/scripts/test_t1_accuracy.py --run-dir /tmp/sim_map --ref-dir /tmp/sim_ref

# T2 建图速度
python3 simulation/scripts/test_t2_speed.py --run-dir /tmp/sim_map

# T3 定位精度
python3 simulation/scripts/test_t3_localization.py
```

### 2.2 合成环境的已知边界（不要外推到硬件）

| 边界 | 说明 |
|:---|:---|
| 参考面是解析平面 | 真实场景的参考面有自身不确定度 |
| 步态是正弦叠加 | 真实触地冲击是宽带脉冲，不是正弦 |
| 场景仅 10×10 m 室内 | 无室外、无长走廊、无玻璃、无动态物体 |
| 无真实 IMU 噪声特性 | 噪声为合成高斯白噪声 + 随机游走 |
| 未测 Orin NX 算力 | 延迟数据来自开发机，非板端 |

**结论**：合成环境的 PASS **不能**用于声明硬件达标。

## 3. 真实场景回环测试方案（缺口 3 的补充）

### 3.1 场景参数

| 项 | 建议值 | 说明 |
|:---|:---|:---|
| 场景 | 实验室/厂房**环形走廊** | 需有足够几何特征；纯长直走廊会退化 |
| 路线长度 | 100 m ± 20 m | 覆盖回环检测的距离尺度 |
| 运动速度 | 0.5–1.0 m/s | 四足常速 |
| 回环次数 | **≥ 3 圈** | 单圈无法区分"回环成功"与"恰好闭合" |
| 地面 | 与目标应用一致 | 打滑影响轮式/足式里程计 |
| 光照 | 若使用相机着色，需与实际一致 | 不影响 LiDAR |

### 3.2 测量工具（三选一，按精度需求）

| 工具 | 适用 | 精度量级 | 备注 |
|:---|:---|:---|:---|
| 全站仪 | 室内，高精度 | mm–cm | 需设置控制点，见 3.3 |
| RTK-GPS | 室外 | cm | 需开阔天空，室内不可用 |
| 激光跟踪仪 | 极高精度需求 | sub-mm | 设备昂贵，适合标定而非长距离 |

**若三项都不可用**：退化为"闭合误差自检"——同一路线重复 ≥ 3 圈，比较每圈起终点位姿差。这**不能**给出绝对精度，只能给出**重复性**，报告中必须如实标注。

### 3.3 控制点布设

| 项 | 要求 |
|:---|:---|
| 数量 | ≥ 6 个 |
| 分布 | 沿路线**均匀**分布，覆盖起点、中途、终点 |
| 形状 | 便于 LiDAR 识别（平面/角点），避免玻璃与镜面 |
| 测量 | 用全站仪测出控制点在统一坐标系下的坐标，记录测量不确定度 |

### 3.4 执行流程

```bash
# 1. 建图（不开定位）
ros2 launch sensing_launch sensing.launch.py config:=lio_orin_nx.yaml
ros2 bag play loop_3laps.bag --clock
# 保存地图与控制点比对

# 2. 定位（加载上一步地图）
# 参考 src/localization/localizer/launch/localizer_launch.py

# 3. 逐圈分析
```

### 3.5 验收指标

| 指标 | 目标 | 不达标时的首要排查 |
|:---|:---|:---|
| 每圈闭合误差 | ≤ 5 cm | 逐点时间字段 → 外参 → PGO 门控 |
| 回环检测成功率 | ≥ 90% | Scan Context 阈值与门控（见 `docs/tuning_guide.md`） |
| 控制点匹配 RMSE | ≤ 5 cm | 外参、体素分辨率 |
| 定位可用率（全段） | ≥ 95% | 启动时间 |

## 5. 退化与边界场景

| 场景 | 为什么危险 | 观察点 | 相关参数 |
|:---|:---|:---|:---|
| 长直走廊 | 沿走廊方向几何退化，LiDAR 无法约束该自由度 | 里程计沿轴向漂移 | `imu_weight` 类权重、`lidar_cov_inv` |
| 楼梯 | 剧烈俯仰 + 垂直运动 | 俯仰估计、点云分层 | 逐点时间字段、步态滤波 |
| 玻璃/镜面 | 虚假回波产生错误平面 | 地图出现"幽灵墙" | `point_quality_thresh` |
| 空旷大厅 | 特征稀疏 | 有效点不足 | `lidar_max_range`、`near_search_num` |
| 动态物体 | 人/车被当作静态地图 | 地图拖影 | 未实现动态滤波（见 `quadruped_adaptation.md` §5） |
| 极限工况 | 高速/急转 | 延迟 p99、丢帧 | 见 §1.4 |

## 6. 证据归档要求

任何声称"已验证"的运行必须留下：

| 项目 | 说明 |
|:---|:---|
| 代码版本 | `git rev-parse HEAD` |
| 配置哈希 | 部署用的 YAML 文件的哈希值 |
